# ADR 0003: Toolchain με .NET 10, global.json και .slnx

* **Κατάσταση:** Αποδεκτή
* **Ημερομηνία:** 2026-10-31

## Πλαίσιο

Το Evolve αναπτύσσεται από τον Οκτώβριο του 2026 έως τον Μάρτιο του 2027 και γίνεται build σε τουλάχιστον δύο περιβάλλοντα: στο μηχάνημα ανάπτυξης και στο CI (Continuous Integration). Στο μηχάνημα ανάπτυξης είναι ήδη εγκατεστημένα SDKs (Software Development Kits) από τις σειρές 8, 9 και 10.

Το SDK δεν καθορίζει μόνο τον compiler. Φέρνει και τους analyzers και τους κανόνες στυλ, οι οποίοι σύμφωνα με το ADR 0004 σταματούν το build σε κάθε warning (`AnalysisLevel` σε `latest-recommended`, `TreatWarningsAsErrors`). Ένα νεότερο SDK μπορεί λοιπόν να σπάσει το build χωρίς καμία αλλαγή στον κώδικα. Χωρίς ρητό κανόνα, το `dotnet` επιλέγει το νεότερο εγκατεστημένο SDK, οπότε το αποτέλεσμα του build εξαρτάται από το τι έτυχε να είναι εγκατεστημένο σε κάθε μηχάνημα.

Χρειάζεται επίσης ένα αρχείο solution που ανοίγει τόσο στο IDE (Rider) όσο και στο `dotnet` CLI (Command Line Interface) και που θα αλλάζει συχνά, καθώς προστίθενται τα περίπου 20 projects του συστήματος.

## Απόφαση

**Framework:** .NET 10, έκδοση LTS (Long Term Support) με υποστήριξη έως τον Νοέμβριο του 2028. Το `net10.0` ορίζεται κεντρικά στο `Directory.Build.props` (ADR 0004).

**SDK:** ένα `global.json` στη ρίζα του repo:

```json
{
  "sdk": {
    "version": "10.0.203",
    "rollForward": "latestPatch"
  }
}
```

Με `latestPatch` το `dotnet` χρησιμοποιεί το νεότερο εγκατεστημένο patch του feature band 10.0.2xx, με ελάχιστο το 10.0.203. Αν δεν βρει SDK αυτού του band, σταματά με σφάλμα αντί να χρησιμοποιήσει άλλο. Η μετάβαση σε νεότερο band (π.χ. 10.0.3xx) γίνεται μόνο με ρητό commit που αλλάζει το `global.json`, ώστε τυχόν νέα warnings των analyzers να εμφανίζονται σε εκείνο το commit και όχι τυχαία στη μέση άλλης δουλειάς.

Το ίδιο αρχείο περιέχει και το κλειδί `test.runner`, που τεκμηριώνεται στο ADR 0006.

**Solution:** `Evolve.slnx`, στο format XML (Extensible Markup Language). Οι solution folders καθρεφτίζουν τους φακέλους του δίσκου (ADR 0001) και τα αρχεία ρυθμίσεων της ρίζας εμφανίζονται ως Solution Items.

## Εναλλακτικές που εξετάστηκαν

* **.NET 11:** απορρίφθηκε. Αναμένεται τον Νοέμβριο του 2026 ως STS (Standard Term Support). Η υιοθέτησή του θα σήμαινε αναβάθμιση major έκδοσης στη μέση της υλοποίησης, χωρίς λειτουργικό όφελος για το Evolve και με τον κίνδυνο οι βιβλιοθήκες τρίτων (π.χ. WolverineFx, Npgsql) να μην έχουν ακόμη ευθυγραμμιστεί.
* **Χωρίς `global.json`:** απορρίφθηκε. Το build θα χρησιμοποιούσε το νεότερο εγκατεστημένο SDK κάθε μηχανήματος, και μια εγκατάσταση για άλλο project θα άλλαζε σιωπηλά το SDK του Evolve.
* **`rollForward` σε `latestFeature`:** ήταν η αρχική ρύθμιση και απορρίφθηκε. Επιλέγει αυτόματα το νεότερο εγκατεστημένο feature band, που μπορεί να φέρει νέους κανόνες analyzers και, λόγω του `TreatWarningsAsErrors`, να σπάσει το build σε ένα μόνο μηχάνημα. Το όφελός του, η αυτόματη μετάβαση σε νέο band, δεν έχει αξία εδώ, αφού οι εγκαταστάσεις SDK γίνονται μόνο με απόφαση του developer.
* **`latestFeature` με `AnalysisLevel` κλειδωμένο σε `10.0-recommended`:** απορρίφθηκε. Θα περιόριζε τον κίνδυνο αλλάζοντας το ADR 0004, όμως οι κανόνες στυλ του `EnforceCodeStyleInBuild` δεν κλειδώνουν με τον ίδιο τρόπο. Αφού το band αλλάζει μόνο ρητά, η επιπλέον προστασία δεν χρειάζεται.
* **`rollForward` σε `disable`:** απορρίφθηκε. Απαιτεί ακριβώς την έκδοση 10.0.203, οπότε κάθε patch ασφαλείας του ίδιου band θα απαιτούσε αλλαγή του `global.json`.
* **`.sln`:** απορρίφθηκε. Το παλιό format περιέχει GUIDs (Globally Unique Identifiers) και επαναλαμβανόμενα blocks ρυθμίσεων, είναι δυσανάγνωστο και δημιουργεί δύσκολα merge conflicts. Το `.slnx` είναι το default του `dotnet new sln` στο .NET 10 και υποστηρίζεται από το Rider.

## Συνέπειες

* **Θετικές:** ίδιο feature band SDK και ίδιοι κανόνες analyzers σε κάθε μηχάνημα. Μια ασυμβατότητα εμφανίζεται ως σαφές σφάλμα επιλογής SDK αντί για απρόσμενα warnings. Το αρχείο solution διαβάζεται και ελέγχεται εύκολα στο code review.
* **Αρνητικές:** όταν κυκλοφορήσει νεότερο feature band, το 10.0.2xx θα σταματήσει κάποια στιγμή να παίρνει patches. Η αναβάθμιση γίνεται χειροκίνητα σε ξεχωριστό commit: εγκατάσταση του νέου SDK, αλλαγή του `global.json`, build και διόρθωση τυχόν νέων warnings. Το CI πρέπει να εγκαθιστά SDK από το ίδιο band, κάτι που θα επαληθευτεί κατά τη ρύθμιση του pipeline. Παλαιότερα εργαλεία που δεν υποστηρίζουν `.slnx` δεν ανοίγουν το solution.
* **Επαλήθευση:** στις 31/10/2026, με εγκατεστημένα τα SDKs 8.0.413, 9.0.202, 9.0.308 και 10.0.203, η εντολή `dotnet --version` στη ρίζα του repo επιστρέφει 10.0.203.
