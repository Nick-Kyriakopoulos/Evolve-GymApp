# ADR 0005: Central Package Management με transitive pinning

* **Κατάσταση:** Αποδεκτή
* **Ημερομηνία:** 2026-10-31

## Πλαίσιο

Το Evolve θα αποτελείται από περίπου 20 projects (τέσσερα layers ανά service, ADR 0002, συν τα projects του `platform/` και τα test projects), που θα μοιράζονται πολλά από τα ίδια πακέτα NuGet: EF Core (Entity Framework Core), Npgsql, WolverineFx, Aspire. Αν κάθε `.csproj` δηλώνει τη δική του έκδοση, οι εκδόσεις αποκλίνουν με τον χρόνο, και δύο services μπορεί να τρέχουν διαφορετική έκδοση της ίδιας βιβλιοθήκης χωρίς να το έχει αποφασίσει κανείς.

Επιπλέον, το ADR 0004 ενεργοποιεί το NuGet audit και για τις έμμεσες (transitive) εξαρτήσεις. Οι βιβλιοθήκες αυτές φέρνουν δεκάδες transitive πακέτα, και όταν ένα από αυτά δημοσιευτεί ως ευάλωτο, χρειάζεται ένας τρόπος να ανέβει η έκδοσή του σε όλο το repo από ένα σημείο.

## Απόφαση

Χρησιμοποιείται CPM (Central Package Management) με ένα `Directory.Packages.props` στη ρίζα:

* **Κεντρικές εκδόσεις:** `ManagePackageVersionsCentrally` σε `true`. Οι εκδόσεις δηλώνονται μόνο ως `PackageVersion` στο κεντρικό αρχείο. Τα `.csproj` περιέχουν `PackageReference` χωρίς `Version`.
* **Transitive pinning:** `CentralPackageTransitivePinningEnabled` σε `true`. Μια γραμμή `PackageVersion` ισχύει και για πακέτα που ένα project χρησιμοποιεί μόνο έμμεσα. Έτσι μια ευπάθεια σε transitive πακέτο (NU1901 έως NU1904, ADR 0004) διορθώνεται με μία γραμμή, αντί για άμεσο `PackageReference` σε κάθε επηρεαζόμενο project.
* **Χωρίς παρακάμψεις ανά project:** `CentralPackageVersionOverrideEnabled` σε `false`. Ένα `.csproj` δεν μπορεί να ορίσει δική του έκδοση με `VersionOverride`. Το κεντρικό αρχείο είναι η μόνη πηγή αλήθειας για τις εκδόσεις όλου του συστήματος.
* **Κανόνες για το περιεχόμενο:** μόνο exact εκδόσεις, χωρίς floating (π.χ. `9.*`). Κάθε γραμμή που υπάρχει μόνο για transitive pinning συνοδεύεται από σχόλιο που εξηγεί γιατί μπήκε (π.χ. ποια ευπάθεια διορθώνει), ώστε να μπορεί να αφαιρεθεί όταν πάψει να χρειάζεται.

## Εναλλακτικές που εξετάστηκαν

* **Εκδόσεις μέσα σε κάθε `.csproj`:** απορρίφθηκε. Επανάληψη σε περίπου 20 αρχεία και απόκλιση εκδόσεων με τον χρόνο.
* **MSBuild properties για εκδόσεις (π.χ. `$(EfCoreVersion)` στο `Directory.Build.props`):** απορρίφθηκε. Είναι ο τρόπος πριν από το CPM: δεν επιβάλλεται, αφού ένα project μπορεί να γράψει απευθείας αριθμό έκδοσης, και δεν καλύπτει transitive πακέτα.
* **CPM χωρίς transitive pinning:** απορρίφθηκε. Οι γραμμές `PackageVersion` για transitive πακέτα θα αγνοούνταν, οπότε το audit του ADR 0004 θα ανέφερε ευπάθειες που δεν διορθώνονται κεντρικά.
* **`VersionOverride` επιτρεπτό:** απορρίφθηκε. Η ανεξαρτησία εκδόσεων ανά service εξυπηρετεί ξεχωριστές ομάδες με ξεχωριστούς ρυθμούς, που εδώ δεν υπάρχουν (βλ. και ADR 0001). Ένα `VersionOverride` δεν φαίνεται στο κεντρικό αρχείο και υπονομεύει την εγγύηση του CPM. Αν προκύψει πραγματική ανάγκη, η ρύθμιση αλλάζει με ρητό commit και σχόλιο.
* **Floating εκδόσεις:** απορρίφθηκε. Το αποτέλεσμα του restore θα εξαρτιόταν από το πότε τρέχει. Το CPM ούτως ή άλλως τις απορρίπτει by default.
* **Lock files (`packages.lock.json` με `--locked-mode` στο CI):** απορρίφθηκε προς το παρόν. Με exact εκδόσεις το NuGet επιλέγει για κάθε transitive πακέτο τη χαμηλότερη έκδοση που ικανοποιεί τα ranges, και τα πακέτα του nuget.org είναι immutable, οπότε το γράφημα εξαρτήσεων είναι ήδη ντετερμινιστικό. Τα lock files θα πρόσθεταν έλεγχο integrity μέσω hash, με κόστος περίπου 20 αρχεία που αλλάζουν σε κάθε αναβάθμιση. **Σημείο επανεξέτασης:** αν προστεθεί δεύτερο package source (π.χ. ιδιωτικό feed), όπου η προστασία από αλλοιωμένα ή ομώνυμα πακέτα αποκτά αξία.

## Συνέπειες

* **Θετικές:** μία έκδοση ανά πακέτο σε όλο το σύστημα, ορατή σε ένα αρχείο. Αναβάθμιση ή διόρθωση ευπάθειας, άμεσης ή transitive, με αλλαγή μίας γραμμής.
* **Αρνητικές:** όλα τα services αναβαθμίζονται μαζί, οπότε μια αναβάθμιση που σπάει ένα service μπλοκάρει και τα υπόλοιπα μέχρι να διορθωθεί. Τα transitive pins παλιώνουν: συνεχίζουν να επιβάλλουν έκδοση ακόμη κι όταν οι βιβλιοθήκες έχουν πια ανέβει μόνες τους, γι' αυτό ελέγχονται σε κάθε αναβάθμιση με βάση το σχόλιό τους. Ένα pin που ανεβάζει πακέτο σε major έκδοση που δεν περιμένει κάποια βιβλιοθήκη μπορεί να σπάσει στο runtime αντί για το build. Αντίθετα, ένα pin χαμηλότερο από ό,τι απαιτεί μια βιβλιοθήκη το πιάνει το NuGet ως downgrade error. Τα templates του `dotnet new` προσθέτουν `Version` στα `PackageReference`, που πρέπει να αφαιρείται.
* **Επαλήθευση:** στις 31/10/2026 προστέθηκε προσωρινά `VersionOverride="4.0.2"` (ίδια τιμή με την κεντρική) στο `Evolve.Members.Domain.Tests.csproj`. Το `dotnet restore --force` απέτυχε με **NU1013** (`The following PackageReference items cannot specify a value for VersionOverride`), άρα η απαγόρευση ισχύει για τη χρήση του `VersionOverride` και όχι μόνο για την απόκλιση έκδοσης. Μετά την επαναφορά, restore και build πέρασαν με 0 warnings και 0 errors.
